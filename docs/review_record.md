# 📝 湖滨四季选股系统 Review 与决策记录

本文件用于记录我们对《湖滨四季每日自动化选股策略草案》进行的 review 及决策过程，确保开发逻辑的一致性与严密性。

## 📌 议题一：知识星球（每日逻辑发掘）PDF 自动获取与解析

### 1. 现状与需求分析
- 每日逻辑发掘数据来源于知识星球（位置：`https://wx.zsxq.com/group/28882585511221`）。
- 格式为 PDF 文件（例如 `daily_morning_summary/每日逻辑发掘_20260701.pdf`）。
- 该 PDF 包含当前最核心的独立产业催化和商业逻辑。

### 2. 备选方案
*   **方案 A (全自动浏览器模拟)**：使用 Puppeteer / Playwright 模拟登录知识星球，检测每日新帖，并自动下载 PDF。
    *   *优缺点*：全自动，但星球有严格的扫码验证、风控，且维持 Cookie 成本高，容易失效。
*   **方案 B (本地监听 + 自动解析)**：系统实现一个本地目录（如 `daily_morning_summary/`）的监听器。用户每日从微信或网页端手动下载 PDF 丢入该文件夹，系统自动触发解析。
    *   *优缺点*：实现简单、极其稳定，无风控问题。只需用户手动拖入一个文件，牺牲微小的自动化度换取 100% 的可靠性。
*   **方案 C (微信转发机器人)**：建立一个微信群机器人，当群内收到星球 PDF 时，自动下载保存到指定目录。

### 3. 当前决策状态
> 👤 **已决策**：采用**双轨混合方案**。脚本定时单次执行，首选自动抓取星球 PDF。如果自动抓取失败，自动发送警报并扫描 `daily_morning_summary/` 下由用户手动下载的 PDF。无需常驻监听文件夹，只需每日通过定时程序在盘前单次运行。

## 📌 议题二：龙虎榜数据自动化获取

### 1. 现状与需求分析
- 需要获取每日“机构席位净买入”数据，用来计算主力资金动向，并为“战法评分”提供数据支持。

### 2. 备选方案
*   **方案 A (第三方公开 API)**：使用如 AkShare (Python库) 直接拉取东方财富或同花顺的每日龙虎榜数据。
    *   *优缺点*：免费、开箱即用，接口稳定。但需要 Python 环境。
*   **方案 B (自建爬虫)**：直接写 Node.js / Python 爬虫爬取东财网龙虎榜页面。
    *   *优缺点*：容易受网页反爬和结构变动影响，维护成本高。
*   **方案 C (商业数据源 API)**：使用聚宽 (JoinQuant) 或 Tushare。
    *   *优缺点*：数据极其稳定，但可能需要付费或积分。

### 3. 当前决策状态
> 👤 **已决策**：采用**方案 A (Python AkShare 库)** 自动拉取。同时**开发方案 B 网页爬虫作为自动兜底方案**（若 API 超时或异常，自动降级抓取东财/新浪等网页）。若网络完全断开或发生其他极端故障，支持读取本地导出的 `longhubang.csv` 格式文件进行最终手动兜底。数据采集开发完毕后，需与用户提供的历史数据进行核对。

## 📌 议题三：盘前利空与利多消息的自动扫描

### 1. 现状与需求分析
- 排除光通信/纯存储板块，主要依据是美股大盘（隔夜美股相关板块如 AAOI, 康宁, 闪迪, 美光, 英特尔等的跌幅）。
- 需要自动获取隔夜美股重点标的的涨跌幅，以及国内盘前重大负面消息。

### 2. 备选方案
*   **方案 A (美股行情 API)**：通过 Yahoo Finance / AkShare 接口，在每日盘前（8:00 - 9:00）拉取设定好的美股重点观测清单（CPO、存储、半导体设备等板块）的涨跌幅。
*   **方案 B (主流财经快讯网络爬虫)**：爬取财联社、新浪财经的盘前快讯，通过大模型判定有无重大利空。

### 3. 当前决策状态
> 👤 **已决策**：采用**方案 A + B 混合模式**。
> * **美股/夜盘硬排除**：拉取隔夜美股 CPO、存储、半导体设备等核心标的的涨跌幅，由代码硬逻辑直接排除对应受挫的 A 股板块。
> * **国内消息扫描**：抓取主流财经快讯（如财联社盘前汇总），通过大模型（LLM）筛选个股是否存在重大利空。
> * **市场环境与模式判定生成**：程序自动拉取美股纳指、标普、费半涨跌幅 + A50夜盘数据 + 财经要闻，将这三部分输入大模型，由大模型自动生成每日的“市场环境与模式判定”综述。

## 📌 议题四：系统技术栈与选股决策流程

### 1. 技术栈选型与 LLM API 运行机制
- **核心逻辑与数据采集**：Python (适合处理 PDF、使用 AkShare 获取龙虎榜及美股行情数据)。
- **Web 可视化与操作界面**：Node.js + HTML + Vanilla CSS (提供持久的 Web 看板服务以供服务器部署)。
- **AI/LLM 驱动与连接机制**：
  * **运行机制**：由 Python 脚本中的 LLM 客户端代码直接发起 API 请求，而非通过 Antigravity 运行。
  * **API 接口支持**：支持配置环境变量或本地配置文件，通过 API Key 调用云端 API（如 Gemini API、OpenAI 接口），同时也支持调用本地 Ollama（如部署 DeepSeek/Llama3）以适应离线及保密部署需求。
- **自定义外部输入 (Notion API)**：
  * 推荐使用 **Notion** 作为外部笔记记录软件（其 API 极其完善友好）。系统将在 Python 中集成 Notion Client 自动获取今日笔记作为决策上下文。
  * **免费会员完全可用**：Notion API 对免费版个人空间完全开放，没有功能阉割。其 3次/秒 的全局流控对于每日单次跑批的选股脚本毫无影响，无扣费和额度超限风险，可完美免费部署。
  * **支持当日多篇 Page 自动合并**：使用 Notion Database 时，系统会使用 Query Database API 拉取当天所有新建或修改的 Page 列表，自动遍历抓取每篇笔记的块内容并安全拼接。在遍历请求时自动增加 `0.4秒` 的防流控间隔保护，稳定拉取并合成为一段当日自定义输入。
  * 兜底方案支持读取本地指定目录下的 Markdown 格式笔记（兼容有道笔记导出或 Obsidian 记录习惯）。

### 2. 架构设计决策
- **选股决策流程**：
  1. **数据拉取**：每日盘前，系统拉取星球 PDF（优先自动模拟，失败则检测本地）、龙虎榜数据、隔夜美股表现、以及 Notion 笔记中的自定义输入。
  2. **初筛排除（量化）**：根据美股暴跌情况直接排除 CPO/存储板块个股。
  3. **技术面过滤**：扫描全 A 股，过滤出符合“21日线企稳、多头排列、流通市值、底部放量”的标的池。
  4. **大模型判定（核心）**：大模型读取星球 PDF 中的“催化题材”，与过滤后的标的池进行语义匹配，提炼出相关个股。
  5. **评分与输出**：对匹配出的个股进行湖滨四季战法打分，输出“首选三标”及其介入条件。
  6. **双输出生成**：生成本地 Markdown 报告文件，并将结果写入 JSON 以供 Node.js Web 可视化后台展示。

### 3. 当前决策状态
> 👤 **已决策**：采用 **Python 脚本 (分析与评分引擎) + Node.js (Web可视化与报告导出服务器)** 架构。严格执行路径一致性铁律。

## 📌 议题五：关于是否采用 RAG (检索增强生成) 架构

### 1. 现状与需求分析
- 选股决策对即时性要求极高，仅看当天和最近几天的语料（星球 PDF、龙虎榜、美股快讯、Notion 个人笔记）。
- 每日这几部分数据合集总 Tokens 数约在 **10K - 30K** 之间，极其轻量。

### 2. 备选方案
*   **方案 A (向量检索 RAG 过滤)**：将当日 PDF 按照 500 字分块，生成 Embedding 并存入向量数据库，运行时让大模型根据个股代码从向量数据库中检索相关段落作为上下文。
    *   *优缺点*：复杂，且可能因为向量相似度匹配不准确，导致大模型漏掉了某些拐点或非显式提及的关联利空（比如“康宁大跌导致CPO受挫”可能无法被个股检索到），直接导致决策错误。
*   **方案 B (长上下文直喂 Full-Context)**：直接利用主流大模型（Gemini 等）数十万的长上下文特性，把当天的全部语料一次性无损地喂给模型进行判定。
    *   *优缺点*：最简单，且模型拥有全局 100% 完整无损的情境认知，逻辑推理和排除精度达最大化。无召回率丢失风险。

### 3. 当前决策状态
> 👤 **已决策**：**在每日选股主流程中，【坚决不采用 RAG】**。采用“全语料直喂 (Full-Context)”架构。极大地降低首期开发复杂度，确保决策的精度为 100%。
> * **未来扩展**：系统会将每日产生的历史数据以**结构化 JSON 格式**持久化。若数月后用户希望进行“历史选股数据智能复盘问答”，我们可将历史 JSON 数据导入一个轻量级本地 RAG（如 ChromaDB）进行检索，该扩展完全不影响盘前的主流程选股逻辑。
